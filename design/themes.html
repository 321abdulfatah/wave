WAVE · design system · per-locale theming

The same door, in fourteen places.

One doorstep card, rendered in every locale theme. The markup is identical in all fourteen — only the custom properties change. What varies is what the research said should vary, and nothing else.

9 of 14 locales get a distinct palette. 5 keep the base, because no sourced reason to depart was found and an unjustified palette is a liability rather than a feature. Two of those 5 still change typeface or text-layout tokens — script coverage is not a matter of taste.

  • Alert semanticsISO 3864-4, not folk symbolism: red = prohibition, yellow = warning, green = safe, blue = mandatory. Legally standardised in every market here, and matched by China's own national safety-colour standard. pt-BR is the one documented exception.
  • WCAG 1.4.1Colour never carries a state alone. Every state below also has an ISO 7010 shape — square, triangle, circle-with-bar — and a text label. Theming may change hue; it may not make hue load-bearing.
  • ContrastMeasured from the hex values, not eyeballed. Every body-text pair in every theme clears AA 4.5:1; the worst case per theme is in the table and every pair is listed under each card.
  • No flags, no costumesA change with no finding behind it did not get made. Where the repo says "no reliable locale-specific colour semantics found", the theme says so too.

"Distinct" means the colour tokens depart from the base. "Type" counts typography tokens that depart — a locale can have a base palette and still need a different typeface, and two of them do.

  1. The caution tier loses its yellow. Hasan, Al-Sammerai & Abdul Kadir (2011), English Language Teaching 4(3):206–213, read in full: yellow reads as envy, sickness, cruelty and dishonesty — "yellow smile = mean". It is not caution here. The warning tier becomes copper, which keeps an amber position in the ISO 3864-4 ordering without the yellow reading.
  2. No surface is white. The same paper gives white as purity and weddings but also the shroud and the coffin — "nearly impossible to change" — so the near-white card (#fffcf6) is warmed to ivory and the paper deepened to sand. White is not the neutral background Western UI assumes it to be.
  3. Green is strengthened rather than merely kept. The source explicitly gives "green light = good sign", so the safe tier is the one place the Arabic reading and ISO 3864-4 agree, and it is worth leaning on.
  4. Blue is deliberately absent. The same paper puts blue with envy, jealousy, death and gloom — the default "informational" colour of every design system. It rests on one paper, so the response is to avoid introducing blue, not to make a claim about it.
  5. Type: Noto Kufi Arabic at the SAME size as the Latin stack (--font-scale: 1). The UAE Government Design System sets Arabic at identical sizes to Latin, which contradicts the common "set Arabic 20–30% larger" advice. Leading goes to 1.7 for the deeper Arabic descenders, and letter-spacing goes to zero because tracking breaks cursive joins.
  6. Layout is RTL via dir="rtl"; the theme sets no physical margins, so components must use logical properties.

Three things this page is deliberately not doing

It is not inventing a Greek, Turkish, Nigerian or American palette. For those four the repo's own research says there is no reliable locale-specific colour semantics, or that the adjacent locale's paper explicitly does not apply. el-GR still changes its display face, because the Google Fonts API serves Fraunces in latin, latin-ext and vietnamese only — a Greek headline in Fraunces silently falls back to Georgia.

It is not treating the Korean red-name taboo as pan-CJK. No source says either way, so --name-ink is simply applied in every theme: a visitor's name renders in body ink everywhere, red stays in the icon and the border. It costs nothing outside ko-KR and it cannot be forgotten.

It is not silently fixing the base. One measured finding is reported rather than patched: the base --ochre (#c58a2b), which app/globals.css uses for the .ring-pulse border, measures 2.72:1 against --paper. WCAG 1.4.11 asks 3:1 of a graphical object that carries state, and for a Deaf resident that ring is the doorbell. #b8801f would clear it at 3.12:1. Changing it restyles the shipped alert in all fourteen locales, so it is a decision for the product, not for a theming pass. Themes that choose their own --ochre — ja-JP, hi-IN, sw-KE, es-MX, fr-FR, ar-*, pt-BR — already clear 3:1.

Where the numbers come from

docs/locale-colour-typography.md (ja, ko, zh) · docs/gesture-research-mena.md (ar, tr) · docs/locale-research-fr-us-ke.md (fr, en-US, sw) · docs/gesture-research-greece-africa.md (el, en-NG) · the colour and text fields on every entry in lib/gestures/locales.ts. Contrast computed with the WCAG 2.x relative-luminance formula over the sRGB values in lib/theme/themes.ts.

en-GB is not themed here: it does not exist in lib/gestures/locales.ts, and adding a locale to invent a theme for it would be the exact failure this page is trying to avoid.
